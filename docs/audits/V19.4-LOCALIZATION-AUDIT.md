# BSR Pro V19.4.0 — Localization Fix Loop Audit

## Implemented in this loop
- Added `localize-pages.js` to login, signup, password-reset, and customer-view pages; it reads the saved `bsp_lang` setting and translates exact phrase matches in static and dynamically-rendered DOM text plus placeholder/title/aria-label attributes.
- Added a language selector to those public pages (English, Hindi, Gujarati, Marathi, Nepali, Telugu), persisting the selection and reloading the page so original strings can be translated consistently.
- Added shared localization script to web packaging and service-worker offline shell.
- Expanded all six locale JSON files from 207 to 241 keys with common dashboard and public-screen labels. Synchronized embedded `v18-i18n.js` locale tables with those JSON files.
- Added regression tests ensuring all five pages load locale resources, public pages load the shared translator, and offline packaging includes it.
- Bumped candidate version to 19.4.0 / derived Android versionCode 190400.

## Validation
- `node --test tests/*.test.mjs`: 175 passed, 0 failed.
- `node scripts/verify-web.mjs`: passed.
- `node scripts/prepare-web.mjs`: passed.
- `node scripts/sync-version.mjs --check`: passed.

## Still not complete — do not claim full translation
- Translation is exact-key based. Many BSR Pro-specific dynamic strings, statements/PDF content, toasts, and newer dashboard text do not have locale entries yet and may remain in English/Hindi in Gujarati, Marathi, Nepali or Telugu.
- Automated tests verify wiring and dictionary parity, not linguistic quality or that every visible phrase is translated. Native-language review and a full runtime string inventory are still required.
- Dashboard has its own `setLang`/`translateStaticDom`; other pages now share the stored selection and selector. Dynamic strings rendered outside text-node/attribute paths (e.g. canvas, generated PDFs, image text) are not automatically translated.

## Release status
Development candidate only. No APK or physical-device localization test was produced in this environment. The Android platform directory and Capacitor CLI dependency are missing, and `ANDROID_HOME` is unset. Do not label this as complete localization or a production release.
