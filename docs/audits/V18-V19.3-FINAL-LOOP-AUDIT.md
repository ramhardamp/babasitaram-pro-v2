# BSR Pro V19.3.0 — Final Loop Audit

## Actual code changes this iteration
- Added `BsrContactsPickerPlugin.java` generation to `scripts/prepare-android.mjs`. On Android it launches the system phone-contact picker only after an explicit tap and reads only the selected name/phone. It does not enumerate the address book and does not request broad `READ_CONTACTS`.
- Registered the native plugin before `super.onCreate()` and exposed it through `native-shim.js`.
- Updated `pickCustomerFromContacts()` to prefer the Android native picker, then fall back to browser Contact Picker, then manual entry. It only fills editable fields; the user must still press Save before a Firestore write.
- Added a V18-style long-range forecast table (up to 50 years; half-year steps for half-yearly compounding) using the canonical `InterestCalc.calculate()` engine, avoiding a duplicate formula implementation. Added numerical cases for simple yearly and half-yearly compound projection.
- Added translated forecast table labels to all six locale dictionaries; each now has 207 keys. Added generator and integration regression tests. Candidate version is 19.3.0; derived Android versionCode is 190300.

## Test results
- `node --test tests/*.test.mjs`: **172 passed, 0 failed**.
- `node scripts/verify-web.mjs`: **102 checks passed, 0 failed**.
- `node scripts/prepare-web.mjs`: passed and produced `www/`.
- Android platform build is not available in this environment: `android/` is absent, npm install did not complete (installed dependency folders are incomplete), `ANDROID_HOME` is unset, and no `adb`/Android SDK was found. The native Java plugin is generated by the preparation script but has not been compiled into an APK or tested on a device.

## Status of requested items
1. **Full translation of all screens — NOT complete.** Six locale dictionaries are packaged (207 keys each). An automated scan of explicit English/Hindi `t()`/`T()` pairs found 420 unique pairs: 53 currently resolve through V18 locale keys and 367 do not. Gujarati/Marathi/Nepali/Telugu unresolved phrases fall back to English. The phrase inventory is in `docs/LOCALIZATION-COVERAGE.md`; PDFs, generated reports and dynamic/accessibility text also need review.
2. **V18 forecast — FEATURE MERGED; exact full parity NOT yet certified.** The new 50-year projection table and half-yearly steps match the behavior visible in the compiled V18 bundle and use the existing tested BSR Pro engine. Exact runtime parity still needs comparison against the original app on identical inputs, because V18 is a compiled NativeScript APK.
3. **Native contacts — CODE ADDED, APK/DEVICE TEST PENDING.** Native system picker generation and registration are implemented; browser/manual fallbacks remain. Actual Android compilation/device validation is blocked by the missing platform/SDK.
4. **Automatic backup — NOT implemented.** Existing integrity-checked manual export/import and backup-age reminder remain. A real independent backup needs a chosen destination, consent, retention policy, security rules/storage configuration and recovery testing.
5. **Push notifications — NOT implemented.** FCM/VAPID credentials, native/web token setup and a trusted sender/backend are not present. No fake toggle was added.
6. **Android platform directory — NOT present.** Capacitor Android platform must be generated/synced after dependencies can be installed.
7. **APK and physical-device test — NOT done.** This cannot be claimed passed without Android SDK/Gradle, successful APK generation, and an available test device.

## Safety notes
- No production Firestore data, deployed hosting, Firebase rules, customer/transaction schema, or signing keys were changed.
- The NativeScript V18 APK does not contain the original editable app source. Reusing its compiled bundle wholesale is not a safe merge strategy.

## Release decision
**Development candidate only — not ready for production.** Forecast and native-contact code now have automated tests, but do not mark the requested list “all pass” yet. Remaining external prerequisites are an installable npm dependency tree, Android SDK/Gradle, a physical device, an agreed backup destination/retention policy, and Firebase Cloud Messaging sender/configuration.
