# BSR Pro V19.1.0 — V18 merge-loop audit

## Actual changes in this iteration
- Integrated all six locale JSON resources extracted from V18: `en`, `hi`, `gu`, `mr`, `ne`, `te` (197 keys per locale).
- Added `v18-i18n.js`, adapting existing BSR Pro `t(en, hi)` calls to V18 locale dictionaries when an exact English/Hindi phrase matches a V18 key. Unmatched phrases intentionally fall back to English.
- Added six-language selector in dashboard Settings.
- Added locale adapter and all locale resources to service-worker offline cache and `prepare:web` asset packaging.
- Added tests for locale key parity and language selector wiring.
- Bumped candidate version to `19.1.0` (Android versionCode formula gives `190100`) and synchronized `app-config.js` and service-worker cache.

## Validation results
- `node --test tests/*.test.mjs`: **165 passed, 0 failed**. A fixture intentionally exercises a missing `MainActivity` marker and emits an error stack before passing; this noisy test fixture remains a cleanup item.
- `node scripts/verify-web.mjs`: all checks passed.
- `node scripts/prepare-web.mjs`: completed; `www/` contains dashboard, adapter, and locale resources.
- `npm run android:build`: **blocked**, not a successful APK build. The Android Capacitor platform project is not present in the supplied source archive, so `scripts/prepare-android.mjs` cannot find `android/app/src/main/java/com/bsrpro/digitalkhata/MainActivity.java`. The environment also did not have a complete installed Capacitor dependency tree / Android SDK. No APK is included or claimed.

## Still not merged — why
- **Full translation of every screen, modal, PDF, and generated message:** current adapter only translates exact phrases matching V18 locale entries; unmatched strings fall back to English. Needs a full string inventory and native review by language.
- **V18 forecast flow:** V18 archive is a compiled NativeScript bundle, not original editable source. BSR Pro already has a calculator and reverse calculations; adding a second forecast engine without runtime parity cases could produce conflicting numbers.
- **Native contacts import:** not copied from the compiled bundle. A safe implementation needs permission/consent flow, contact selection, duplicate detection, and confirmation before writing to Firestore.
- **Rewards/subscription:** only terminology/resource strings were evidenced, not a complete working flow or entitlement logic. Not safe to invent a billing system.
- **Automatic backup, Crashlytics, push notifications:** these require product decisions, provider/configuration, permissions, failure handling and recovery tests; not safely inferred from V18 strings.
- **Android packaging and real-device tests:** blocked until the Capacitor Android platform, npm dependencies and Android SDK/Gradle environment are installed.

## Protected areas
No changes were made to `ledger.js`, interest calculation formulas, Firestore security rules, PIN security, backup import/recovery algorithms, or customer/transaction schema in this iteration. No production data, Firebase configuration, signing credentials, or deployed app was modified.

## Recommendation
Treat this as a **V19.1.0 merge candidate**, not a release APK. Next restore/install the Android build prerequisites, run the Android build, then test install/update, offline sync, locale switching, backup/restore, and financial parity on a real device before distribution.
