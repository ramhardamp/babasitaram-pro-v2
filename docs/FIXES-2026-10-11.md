# Fixes from full E2E audit (11 Oct 2026)

Tested in real Chromium with an in-memory Firebase mock (tests/e2e-sandbox: `python3 tN.py` while `python3 -m http.server 8765` serves the project).

## 1. Login page flashed on every app start (FIXED)
index.html: returning users (saved-session hint `bsp_userId`) now see a splash while Firebase restores the session, then go straight
to the dashboard. First launch / logged-out users still see the login form immediately. 8s safety net. Logout clears the hint.

## 2. Biometric (fingerprint / face) unlock did not exist (IMPLEMENTED)
- Native plugin `BsrBiometricPlugin` (androidx.biometric BiometricPrompt) is generated by scripts/prepare-android.mjs,
  registered BEFORE super.onCreate, with the `androidx.biometric:biometric` Gradle dependency and USE_BIOMETRIC permission
  added automatically (also in Play-safe builds). Older prepared Android projects are migrated.
- Settings -> Security -> "Biometric Lock" toggle (needs a fingerprint/face enrolled on the phone; turning it OFF needs the PIN).
- When ON: the app locks at every start (not right after typing the password) and after 30s in background.
  Unlock = automatic biometric prompt, the "फिंगरप्रिंट / फेस से अनलॉक" button, or the PIN (fallback).
- Android Back cannot bypass the lock; nothing can paint over the lock screen. Biometric also works on PIN prompts (edit/delete).
- CI/release workflows verify the plugin registration + gradle dependency.
- Browser/PWA: biometric is APK-only (toggle explains this).

## 3. SMS notifications could never turn ON in the APK (ROOT CAUSE FIXED)
prepare-android.mjs registered the native plugin AFTER `super.onCreate()`. Capacitor 7 builds the bridge inside `super.onCreate()`
(BridgeActivity.load() uses `initialPlugins` at that moment), so the plugin was never loaded and every SMS call failed.
Now `registerPlugin(...)` runs BEFORE `super.onCreate()`; CI fails the build if the order is wrong.
Direct (automatic) SMS is ON by default in every build path; Play-Store-safe build: ENABLE_DIRECT_SMS=false.
Saved ON state is shown after reopening the app; clear toasts for browser/PWA, non-SMS build, denied permission, plugin error.
Automatic SMS needs: Android APK + SEND_SMS permission granted. SEND_SMS is restricted on Google Play (use for side-loading).

## 4. Other fixes
1. PIN-gated edit/delete (txn, loan, customer) left the user stuck on the PIN screen -> restorePinOriginScreen().
2. CSV / Excel export ALWAYS failed and would have exported the secret portal viewToken -> sanitized.
3. Landscape / short screens: customer list collapsed to 0px -> @media (max-height:480px).
4. Phone fields (add/edit customer, signup): pasting "98765 43210" lost the last digit -> sanitised on input.
5. Edit customer: balance field was editable but ignored -> readonly; email now validated.
6. Default interest rate: 0/negative accepted, silent failure -> validated 0-100 + toast.
7. Edit loan: portal sync failure showed "Error" although saved -> non-fatal.
8. Edit transaction: rejected if deleted meanwhile. deleteLoan guard made explicit.

## Not testable here (needs a real phone)
Real fingerprint/face prompt and real SMS delivery, Android WebView file downloads (Excel/CSV/backup), PDF print via window.open,
real Firebase rules/network, QR image (needs internet).

# Update 2 (11 Oct 2026): SMS permission block + APK update fail

## 5. SMS permission "App was denied access to SMS ... Learn how to allow access" (FIXED)
- Issue: Android 13+ par APK file se install (side-load) hui app ka SEND_SMS "Restricted settings" me block hota hai. Dialog khud Android ka hai,
  isliye code se permission zabardasti allow nahi ho sakti.
- Fix: native `BsrSmsScheduler.openAppSettings()` (App info page kholta hai) + dashboard `showSmsRestrictedGuide()`.
  Permission deny hone par Hindi steps dikhte hain aur "OK" par App info khulta hai.
- Logic (user ko ek baar karna hai): App info -> upar kone me 3 dots -> "Allow restricted settings" -> Permissions -> SMS -> Allow -> Automatic SMS ON.
  (3 dots tab hi dikhta hai jab ek baar permission maangi gayi ho; pehle toggle dabake dialog band karein, phir App info kholein.)

## 6. Naya APK purani app ke upar install/update nahi hota - "App not installed" (ROOT CAUSE FIXED)
- Issue: android-ci.yml `assembleDebug` banata tha. GitHub ke fresh runner par har baar naya random debug.keystore banta hai, isliye har APK ka
  signature alag tha. Android same package par alag signature wala update reject karta hai.
- Fix: debug APK bhi release.yml wali SAME keystore (4 GitHub secrets) se sign hota hai (`configure-android-signing.mjs --debug`).
  CI non-PR build me secrets na ho to saaf error ke saath fail hoti hai; `apksigner --print-certs` se SHA-256 digest log hota hai (har build me same hona chahiye).
- Ek baar ka kaam: jo app abhi phone me hai wo purani random key se signed hai, uske upar naya (stable-key) APK install nahi hoga.
  Us ek baar purani app uninstall karein (data Firebase me hai; uninstall se pehle koi pending/unsynced entry sync kar lein), phir naya APK install karein.
  Uske baad har naya APK seedha update hoga.

## 7. SMS: Settings se wapas aate hi Automatic SMS khud ON (11 Oct 2026)
- Logic: `armSmsResumeCheck()` App info kholne ke baad ek baar visibilitychange sunta hai; wapas aane par `checkPermission()` granted ho to
  `toggleSmsSetting('enabled')` chalta hai. Granted nahi ho to kuch nahi hota (guide dobara nahi aata).
- Android ka "Restricted settings" gate code se hata nahi sakte; "Allow restricted settings" ek baar karna padta hai. Wo app ke saath tab tak rehta hai
  jab tak app uninstall na ho. Signing key ab stable hai, isliye update uninstall ke bina hota hai => permission bani rehti hai.

## 8. Keyboard khulne par "पेमेंट दें / भुगतान लें" sheet ka Save/rakam keyboard ke peeche chhup jata tha (11 Oct 2026)
- Issue: Android WebView (edge-to-edge) keyboard khulne par page ko resize nahi karta; bottom-sheet ka neeche ka hissa (note, tarikh, Save)
  keyboard ke neeche dab jata tha aur likhi hui rakam bhi aadhi dikhti thi.
- Fix: modal ke andar koi field (input/select/textarea) focus ho to overlay par `kb-open` class lagti hai: sheet screen ke upar aa jati hai,
  max-height 50vh, andar scroll. Blur par wapas normal. Sirf phone width (<500px); desktop/tablet par koi badlav nahi.
- Test: Chromium (360x780) me focus par sheet upar (keyboard ki line se bahut pehle) aur blur par normal. Asli phone par keyboard check baaki.

## 9. "पेमेंट दें / भुगतान लें" sheet ko professional look (11 Oct 2026)
- Issue: sheet "local" lagti thi (emoji title, bhaari gradient, upar floating gap, saade fields).
